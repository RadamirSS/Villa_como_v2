# Архитектура данных и приложения

## Поток данных

```
Рабочие листы MÈTRE + отдельные owner confirmations
         ↓ (ручная/полуавтоматическая оцифровка с provenance)
Canonical FloorGeometry (мм, стабильные ID, подтверждённые замеры)
         ↓
    ┌────┴────────┐
  2D plan      3D scene
    └────┬────────┘
        Shared element IDs
         ↓
Мебель / сантехника / материалы / группы света
```

## Дерево
- `src/data/project.json` — подтверждённые площадные показатели, уровень и источники (этап 0).
- `src/domain/types.ts` — контракты `FloorGeometry`, `WallSegment`, `Opening`, `Room`, `ElementPlacement` и `SourceEvidence`.
- `src/domain/project.ts` — загрузка метаданных с защитой от фиктивной геометрии.
- `src/App.tsx` — экран подготовки, переключение паспортов уровней.
- `scripts/verify-data.mjs` и `tests/` — числовые проверки исходных ведомостей.

## Условия для будущей модели
- Все зоны и проёмы имеют уникальные и стабильные ID; двери ссылаются на ID конкретной стены.
- Размещения мебели/сантехники ссылаются на ID комнаты и каталожного изделия.
- Единожды оцифрованная геометрия служит источником для SVG/DXF 2D и Three.js 3D. Не дублировать массивы координат.
- Отдельные слои: существующее/демонтировать/возвести/готовая отделка; показать итоговую конфигурацию по умолчанию.
- 3D поверх канонической геометрии, а не набор интерпретированных коробок.
- Проверять касания, пересечения, размеры, толщины и ссылочную целостность.
- В перспективе: versioned migrations каждого формата и fixtures для regressions.

## Технологический выбор
React 18, TypeScript 5.7, Vite 6, npm scripts; клиентское приложение без бэкенда на этапе 0. В следующем этапе целесообразны SVG/Canvas 2D и общая модель; `@react-three/fiber` подключать **только** когда геометрия готова к построению в 3D.

## Миграция v1
Не импортировать координаты `architecture.js` из v1 как источник истины. UX и визуальные идеи можно адаптировать позднее с отдельной проверкой. Нет связи с реальными системами умного дома.
